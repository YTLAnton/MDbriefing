# MDbriefing — 自然語言 → Markdown → 互動 HTML 簡報

> 一套個人簡報工作流的地基：跟 AI 討論一個主題 → 整理成一份 Markdown 原稿 → 轉成漂亮、可互動的 `.html` 投影片 → 在瀏覽器給需求方瀏覽或交付。

## PDM Summary（白話、≤200 字）

**這個專案做什麼**：讓你「用講的」就能做出一份漂亮的網頁簡報。你只要跟 AI 把內容聊清楚、整理成一份照著範本填好的 Markdown 檔，之後就能把它變成一份**一頁一螢幕的投影片**——滾輪或方向鍵翻頁、右側圓點目錄可跳頁、細節可展開收合、卡片與時間軸會依序浮現，直接丟給需求方在瀏覽器看。

**目標成果長什麼樣**：**形態**對齊基準簡報（全螢幕投影片、滾動吸附、四個互動）；**視覺不對齊任何外部簡報**——預設是本專案原有的深色系（近黑底＋金色重點）。底色與標誌是兩個獨立的選擇，依觀眾各自決定：`theme: dark / light`、`logo: none / tomoaid / 客戶`。

**還沒做的**：把 Markdown 自動轉成 HTML 的腳本（目前由 AI 照對照表手工轉）、上線部署。

## 目錄結構

```
MDbriefing/
├── README.md                      ← 本檔：專案總覽 + 工作流程
├── content/                       ← 放你寫好的 Markdown 簡報原稿（一份簡報一個 .md）
│   └── demo.md                    ← golden 對照組原稿（對應 briefings/demo/index.html）
├── templates/
│   └── briefing-template.md       ← 空白簡報範本（照填即可，不需寫程式）
├── docs/
│   └── briefing-spec.md           ← 簡報規格書（設計系統、16 種區塊、四互動、MD↔HTML 對照表）
├── assets/                        ← 共用設計系統（真理來源，產出時內嵌進 HTML）
│   ├── deck.css                   ← 形態 + 預設深色 token + 版面語彙 + 響應式 + 列印
│   ├── deck.js                    ← 逐項浮現 / 目錄跳轉 / 數字增長 / 鍵盤與點擊翻頁
│   ├── themes/                    ← 配色主題（底色）：dark.html（預設）、light.html
│   └── logos/                     ← 標誌：tomoaid.html（官方原色）
├── briefings/                     ← 產出的 .html（自包含單檔，打開即可互動）
│   ├── demo/index.html            ← deck 形態 golden 對照組：用滿規格所有區塊
│   ├── _previews/                 ← 同一份內容的四種底色 × 標誌組合，供挑選比較
│   ├── AD_data_transfer_bot/      ← doc 形態：行銷數據自動化工具報價（已交付）
│   └── Self-Media_Course_CardGame/← doc 形態：自媒體課程卡牌遊戲報價（已交付）
└── _PM/
    ├── harness/                   ← Sprint 紀錄
    └── resource/                  ← 形態基準簡報（TomoAid 內部文件，未入版控）
```

| 資料夾 | 一句話用途 |
|---|---|
| `content/` | 放你照範本填好的 Markdown 簡報原稿，每份簡報一個 `.md` 檔。 |
| `templates/` | 放空白簡報範本；開新簡報時複製 `briefing-template.md` 來填。 |
| `docs/` | 放規格書；`briefing-spec.md` 定義設計系統、區塊結構與互動行為。 |
| `assets/` | 共用樣式、互動、配色主題與標誌的**真理來源**；改設計改這裡。 |
| `briefings/` | 放產出的 `.html`；每份一個子資料夾。含兩種形態（見下）。 |

### 兩種產出形態：`deck` 與 `doc`

| 形態 | 是什麼 | 用途 | 誰在操作 | 規格書適用？ |
|---|---|---|---|---|
| **`deck`** 投影片 | 一頁一螢幕、滾動吸附、可換底色與標誌 | 會議上帶著人一頁一頁走 | 你（簡報者） | ✅ 全部條文 |
| **`doc`** 報價文件 | 單欄 760px、可折疊卡片捲動式 | 客戶自己上下滾、比對金額 | 客戶（自行閱讀） | ❌ 不適用 |

兩者差別在**形態**不在配色（預設都是專案深色系），**用途相反所以刻意不互相套規格**：報價要能來回比對金額，捲動式長文件比投影片好用。`briefings/` 底下那兩份 `doc`（皆已交付客戶）維持原樣，不改視覺也不改文案。`doc` 形態目前各自寫死 CSS、沒有共用樣式——等真的出現第三份報價需求再抽；新的報價若想走 deck 視覺，直接做成 deck 即可。

### 為什麼 `assets/` 是共用的，產出卻是單檔？

`assets/deck.css` / `deck.js` / `themes/*.html` / `logos/*.html` 是所有簡報共用的設計系統——改一處，之後每份簡報都受益。但交付給需求方時是把**一個 `.html` 檔**傳出去，若用相對路徑外連，對方電腦上就會失效。所以規則是：**共用來源放 `assets/`，產出時整段內嵌進 `.html`**。改了 `assets/` 就把受影響的簡報重新內嵌一次，不要只改產出的 HTML。

## 工作流程（白話、5 步）

1. **討論**：跟 AI 把要做的簡報主題、章節、重點聊清楚。
2. **整理成 MD**：複製 `templates/briefing-template.md`，把討論結果照提示填進 `content/你的主題.md`。
3. **轉成 HTML**：照 `docs/briefing-spec.md` §六的 MD↔HTML 對照表，把 MD 內容對應成一份 `.html`，並內嵌 `assets/` 的樣式、互動、主題與標誌。產出放 `briefings/你的主題/index.html`。
4. **瀏覽**：用瀏覽器打開該 `index.html`，操作翻頁 / 目錄跳轉 / 展開收合確認呈現正確。
5. **交付**：把該 `.html`（自包含單檔）直接傳給需求方。

> 📌 第 3 步目前**沒有腳本**，由 AI 依對照表手工轉換（`briefings/demo/index.html` 就是這樣做出來的 golden 範例）。自動化留待後續 sprint。

## 簡報長什麼樣、怎麼操作

- **一頁一螢幕**：預設近黑底（#0d0f14）＋淺灰字（#e4e8f2）＋金色重點（#d4a843），圓角卡片與重點色虛線驗收框。
- **底色與標誌分開換**（`.md` 兩行）：

  | 想要的效果 | 寫法 |
  |---|---|
  | 黑底、不掛標誌（大部分場合） | 兩欄都省略 |
  | 黑底 + TomoAid | `logo: tomoaid` |
  | 白底 + TomoAid | `theme: light` ＋ `logo: tomoaid` |
  | 白底、不掛標誌（給客戶的提案） | `theme: light` |
  | 客戶色系 + 客戶標誌 | 各放一個檔到 `themes/` 與 `logos/`，兩欄填檔名 |

  四種組合的實際樣子可直接打開 `briefings/_previews/`（內容相同，只差那兩行）。

  兩個主題都提供同一組八個色名（`gold` `blue` `green` `yellow` `purple` `teal` `coral` `navy`），各自給適合該底色的值，所以**同一份 `.md` 換底色不會脫色**，小字也維持 WCAG AA 對比。
  **標誌一律用官方原色、絕不改色**；黑底會自動加一層淺色底片讓標誌完整可見（可用 `底片：無` 關掉）。
- **四個互動**：
  1. **翻頁** — 滾輪自動吸附；`→` `↓` 下一頁、`←` `↑` 上一頁、`Home` / `End` 到頭尾；**空白處單擊滑鼠左鍵也是下一頁**（點在連結、可折疊標題、目錄或正在選字時不會誤觸）。
  2. **目錄跳轉** — 右側固定圓點，點擊跳頁，滑過才展開標題；目前頁的圓點放大並轉為該頁重點色。
  3. **可折疊** — 細節預設收合，點標題列展開（原生 `<details>`）。
  4. **逐項浮現** — 卡片、流程、時間軸進入畫面時依序淡入。
- **零外部資源**：不連 CDN、不連外部字型或圖片，`file://` 雙擊即可完整運作，離線可用。
- **響應式**：≤760px 自動降為單欄。
- **可列印**：列印 / 匯出 PDF 時自動取消吸附、一頁一張、展開所有折疊內容。
